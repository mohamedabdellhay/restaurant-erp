# دليل نظام الحجوزات للفرونت إند (Frontend Reservation Guide)

هذا الملف يشرح كيفية التعامل مع نظام الحجوزات في تطبيق الـ ERP، بما في ذلك الميزة الجديدة لطلبات الحجوزات العامة (Reservation Requests).

## نظرة عامة (Overview)

نظام الحجوزات مقسم إلى جزئين:

1. **طلبات الحجوزات (Guest/Public)**: تسمح للعملاء بطلب حجز طاولة من خلال واجهة عامة.
2. **إدارة الحجوزات (Admin/Manager)**: تسمح للإدارة بمراجعة الطلبات، تأكيدها، أو إنشاء حجوزات جديدة مباشرة.

---

## تفاصيل الروابط (Endpoints)

### 1. طلب حجز جديد (Guest Reservation Request)

هذا الرابط متاح للجميع (بدون تسجيل دخول).

- **الرابط:** `POST /api/reservations/request`
- **الجسم (Request Body):**

```json
{
  "name": "اسم العميل",
  "phone": "رقم الهاتف (يستخدم للتعرف على العميل)",
  "restaurant": "ID الخاص بالمطعم (مطلوب)",
  "email": "بريد العميل (اختياري)",
  "reservedAt": "2026-02-15T19:00:00Z", // تاريخ ووقت الحجز (ISO8601)
  "numberOfGuests": 4, // عدد الأفراد
  "table": "697b6...", // معرف الطاولة (اختياري - في حال اختار العميل طاولة معينة)
  "notes": "ملاحظات إضافية (اختياري)"
}
```

- **الاستجابة الناجحة (201 Created):** الحجز ينشأ بحالة `pending`.

---

### 2. إدارة الحجوزات (إدارة فقط - Protected)

يتطلب توكن صلاحيات (Admin/Manager).

#### - عرض كافة الحجوزات:

- **الرابط:** `GET /api/reservations`
- **التصفية:** يمكن استخدام `status=pending` لعرض الطلبات الجديدة فقط.

#### - تحديث حالة الحجز (Confirm/Cancel):

- **الرابط:** `PATCH /api/reservations/{id}`
- **الجسم:**

```json
{
  "status": "confirmed", // أو "cancelled", "completed"
  "table": "697b6..." // لا بد من تحديد طاولة عند التأكيد إذا لم تكن محددة
}
```

---

## سير العمل (Workflow)

### أ- رحلة العميل (Guest Flow):

1. العميل يملأ نموذج الحجز في واجهة الموقع.
2. يختار التاريخ، الوقت، عدد الأفراد، والطاولة (اختياري).
3. يتم إرسال الطلب إلى `/api/reservations/request`.
4. النظام ينشئ سجل حجز بحالة **Pending**.

### ب- رحلة الإدارة (Admin Flow):

1. المسؤول يرى الحجز الجديد في لوحة التحكم.
2. يتم فحص توفر الطاولة في الوقت المطلوب.
3. يتم تحديث الحالة إلى **Confirmed** وتخصيص الطاولة (إذا لم تكن محددة).

---

## ملاحظات هامة للفرونت إند:

1. **التعرف على العميل:** النظام يستخدم `phone` للبحث عن العميل. إذا كان موجوداً سابقاً يتم ربط الحجز بملفه، وإذا كان جديداً يتم إنشاء سجل عميل جديد تلقائياً.
2. **التحقق من البيانات (Validation):**
   - وقت الحجز يجب أن يكون في المستقبل.
   - عدد الأفراد يجب أن يكون 1 على الأقل.
   - الطاولة اختيارية في طلب العميل لكنها ضرورية جداً لإدارة المطعم لاحقاً.
3. **التنسيق الزمني:** يفضل إرسال التواريخ بصيغة `ISO 8601` (UTC) لضمان الدقة وتجنب مشاكل المناطق الزمنية.
