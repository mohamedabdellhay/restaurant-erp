# دليل نظام الطلبات ونقاط البيع (Orders & POS Guide)

هذا الملف يشرح كيفية التعامل مع نظام الطلبات (Orders) وعمليات البيع (POS) وإصدار الفواتير (Invoices).

## نظرة عامة (Overview)

> [!IMPORTANT]
> **تنبيه هام للفرونت إند**: تم تفعيل بروتوكول عزلة البيانات (Multi-Tenancy). يرجى مراجعة [دليل التكامل الأساسي (Frontend Integration Guide)](./FRONTEND_API_README.md) لفهم كيفية التعامل مع البيانات المعزولة.

نظام الـ POS يعتمد على ثلاث مراحل أساسية:

1. **إنشاء الطلب (Create Order)**: اختيار الأصناف وتحديد نوع الطلب (طاولة، سفري، أو توصيل).
2. **متابعة التنفيذ (Order Tracking)**: تحديث حالة الطلب من التحضير إلى التقديم.
3. **الدفع والتحصيل (Billing & Payment)**: إصدار الفاتورة وتوثيق عملية الدفع.

---

## تفاصيل الروابط (Endpoints)

### 1. إنشاء طلب جديد (Create Order)

- **الرابط:** `POST /api/orders`
- **الجسم (Request Body):**

```json
{
  "type": "dineIn", // أو "takeaway" أو "delivery"
  "table": "697b6...", // معرف الطاولة (مطلوب في حالة dineIn)
  "customer": "6987a...", // معرف العميل (اختياري)
  "items": [
    {
      "menuItem": "معرف الصنف من المنيو",
      "qty": 2,
      "modifiers": [
        // إضافات مثل (بدون بصل، زيادة صوص)
        { "name": "Extra Cheese", "price": 5 }
      ]
    }
  ]
}
```

---

### 2. تحديث حالة الطلب (Update Order)

يستخدم لتغيير حالة الطلب أثناء العمل (مثلاً من "معلق" إلى "في المطبخ").

- **الرابط:** `PUT /api/orders/{id}`
- **حالات الطلب (Statuses):**
  - `pending`: طلب جديد.
  - `in_kitchen`: جاري التحضير.
  - `served`: تم تقديم الطلب للعميل.
  - `paid`: تم دفع الحساب.
  - `cancelled`: تم إلغاء الطلب.

---

### 3. إصدار الفاتورة (Invoicing)

بعد انتهاء العميل، يتم تحويل الطلب إلى فاتورة.

- **الرابط:** `POST /api/invoices`
- **الجسم:**

```json
{
  "orderId": "معرف الطلب (Order ID)"
}
```

#### - تحديث حالة الدفع:

- **الرابط:** `PUT /api/invoices/{id}/status`
- **الجسم:**

```json
{
  "status": "paid", // أو "unpaid"
  "method": "cash" // أو "card", "online", "wallet"
}
```

## سير العمل (POS Workflow)

1. **الموظف (Waiter/Cashier)** يفتح واجهة الـ POS.
2. يختار الأصناف ويضيف الملاحظات (Modifiers).
3. يحدد نوع الطلب (إذا كان Dine-in يختار الطاولة).
4. يرسل الطلب -> يظهر مباشرة للشيف في شاشة المطبخ.
5. **الشيف** يغير الحالة إلى `in_kitchen` ثم `served`.
6. عند رغبة العميل في الدفع، يضغط الموظف على "إصدار فاتورة" (Generate Invoice).
7. يتم اختيار وسيلة الدفع وتحديث حالة الفاتورة إلى `paid`.

## ملاحظات هامة للفرونت إند:

1. **الحسابات التلقائية:** الباك إند يقوم بحساب (Subtotal, Tax, Service Charge, Total) تلقائياً عند إنشاء الطلب أو الفاتورة. لا داعي لإرسال هذه القيم.
2. **توفر الأصناف (Availability):** كل صنف في المنيو يحتوي على حقل `isAvailable`. يتم حساب هذا الحقل تلقائياً بناءً على المخزون (Inventory). يرجى تعطيل اختيار الأصناف التي تكون `isAvailable: false`. لمزيد من التفاصيل راجع [دليل المنيو](./MENU_API_DOCUMENTATION.md).
3. **ربط الطاولات:** عند اختيار `dineIn` في الطلب، سيتم تغيير حالة الطاولة في النظام إلى `occupied` تلقائياً.
4. **الأذونات:** جميع روابط الطلبات والفواتير تتطلب تسجيل دخول (Bearer Token) ويجب أن يكون للمستخدم صلاحيات (Waitress, Cashier, Manager, or Admin).
